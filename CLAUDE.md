# Тёмный рубеж

Браузерная tower defence в стиле тёмного фэнтези. React 19 + Vite 8 + TypeScript + Tailwind 4,
игровой движок свой (Canvas 2D, без игровых библиотек), звук синтезируется через Web Audio.
Фигуры башен, врагов и боссов — спрайты из `public/sprites/` (см. «Спрайты»); всё остальное
рисуется кодом. Проект начат в Google AI Studio, его остатки убраны.

Владелец — Артур, играет сам, на телефоне и компьютере (macOS). Общение — по-русски.

## Правила

- **Интерфейс игры только по-русски.** Все видимые игроку строки (названия, описания, подсказки,
  ошибки валидации) пишутся по-русски. Идентификаторы и комментарии в коде — как в окружающем коде.
- **Без внешних сервисов, кроме аккаунтов.** Никаких API, аналитики, CDN, `.env`-секретов. Игра
  целиком работает в браузере без входа; прогресс хранится в `localStorage`. Единственное исключение
  (выбор Артура, 2026-10-24) — необязательный аккаунт на Supabase (`src/cloud.ts`): вход через Google или по коду из
  письма, синхронизация прогресса между устройствами. В коде только публичный anon-ключ, доступ к
  строкам ограничен RLS; ключ service_role в репозиторий не класть.
- **Баланс и механику меняем только по замечаниям Артура.** Числа в `config.ts` и формулы в
  `rules.ts` без его просьбы не трогать (рефакторинг без изменения поведения — можно).
- **Одна правка — один коммит.** После каждой правки прогнать lint, тест и сборку (см. ниже).
- **В `main` не вливать без явного «да» Артура.** Работа идёт в отдельной ветке.
- Должно работать и на телефоне (касания, альбомная ориентация), и с клавиатуры на компьютере.
- При нескольких равноценных вариантах — спросить Артура (2–3 варианта, критерий, рекомендация);
  если оптимальный вариант очевиден — решать самому.

## Команды

```bash
npm install          # установка зависимостей
npm run dev          # дев-сервер на http://localhost:3000 (слушает 0.0.0.0 — можно открыть с телефона в той же сети)
npm run lint         # проверка типов: tsc --noEmit
npm test             # тест логики src/game/logic.test.ts (node:test через tsx)
npm run build        # сборка в dist/
npm run preview      # локальный просмотр сборки
```

Проверка после каждой правки: `npm run lint && npm test && npm run build`.

Тест баланса ботом: `npm run dev`, затем `node scripts/balance_sim.mjs out.json [--runs=N] [--only=endless|campaign|mono] [--race=humans|orcs|undead|cultists|demons|elves|all]`
(нужен Playwright; бот играет на настоящем движке с игровым временем, итог — JSON с уроном, золотом, дошедшими врагами и уроном артефакту по видам — `castleDmg`). Пробные числа без правки кода: `--set=siege.attack.shaman.range=2,lives.start=300`; после правки `config.ts` перезапустить дев-сервер, иначе HMR даёт боту старую копию `CONFIG`.

Выкладка: `.github/workflows/pages.yml` на каждом PR прогоняет lint, тест и сборку, а при вливании в
`main` выкладывает `dist/` на GitHub Pages (https://tzzoteozztot-ui.github.io/game/). Сборка с
`base: './'`, поэтому все пути в коде — относительные (`sprites/…`, а не `/sprites/…`).

Поток данных: `App` создаёт один `GameEngine`, отдаёт ему canvas, вызывает публичные методы
(`startLevel`, `startNextWave`, `placeTower`, `mergeSelectedTower`, `sellTower`, `upgradeTier`…).
Движок сообщает о себе через колбэки `onStateChange(GameStateSnapshot)` и `onNeedSpecChoice(tower)`;
React хранит снимок в состоянии и рисует по нему оверлеи. Сам холст React не перерисовывает.
Для отладки движок доступен как `window.gameEngine`.

Магазин (генерация карточек, тройки) живёт в `App.tsx`, а не в движке.

Раскладка зависит от формы окна (`pickLayout` в `App.tsx`, ResizeObserver, выбор Артура 2026-10-31: «под любой экран как будто сделано под него»): на широких экранах — боковая колонка справа, на более квадратных (iPad, 4:3, 16:10) — полоса под полем (`BOTTOM_VARS`, высота от 150 px, в дуэли 176): лавка, рюкзак и кнопки в ряд, `--shop-cols`, `--ctl-cols`, `--ctl-w`, список скоростей открывается вверх (`dropUp`); выбирается та, где поле крупнее.

Боковая колонка — кнопки игры (`GameControls`: скорость, звук, весь экран, пауза — перенесены с поля 2026-10-31), лавка и рюкзак
(в дуэли ещё вкладки «Башни»/«Армия»). Поле занимает всю высоту, колонка — остаток ширины, не уже `max(132px, 12cqw)` и не шире
340 px (просьба Артура 2026-10-31: без полос вокруг поля); в узкой колонке подписи короче — «Лавка», «Ярус 1→2», в руке только
название, у «Обновить» и врагов армии только значок. В бою поле заходит под вырез камеры (`#root:has(.game-stage)` без боковых
отступов), колонка держит свой отступ справа. Золото, жизни, волна и карточка башни —
полупрозрачные оверлеи на поле; касания берут только их кнопки. Колонка — size-контейнер: размеры шрифтов и кнопок задаются
переменными `SIDE_VARS` в `App.tsx` (`--fs-*`, `--h-*`) через `cqh`/`cqw` с минимумами для телефона.

Ключи `localStorage`: `dark_frontier_race` (раса игрока), `dark_frontier_unlocked`, `dark_frontier_stars`, `dark_frontier_sound`,
`dark_frontier_autostart`, `dark_frontier_endless_best` (рекорд волны бесконечного режима по уровням), `dark_frontier_auth`
(сессия Supabase), `dark_frontier_random_map` (бесконечный режим: «Дорога: Случайная»). Звёзды и рекорд волны бесконечного режима хранятся отдельно по сложностям (`stars` и `endlessBest`: `easy|normal|hard`, уровень → число); старые общие значения при чтении переходят в «Обычную». Рекорд пишется с началом каждой волны, поэтому выход в меню посреди забега его не теряет. Прогресс привязан к владельцу (выбор Артура 2026-10-27): гостевой — в ключах выше, у каждого аккаунта своя копия на устройстве `dark_frontier_progress_<id>`; вход в другой аккаунт или выход подменяет прогресс, чужой не подмешивается. Гостевой переносится в аккаунт один раз, только если у аккаунта (устройство + облако) прогресса ещё нет, и после переноса гостевая копия обнуляется. В аккаунте прогресс лежит в таблице `progress` (`user_id`, `data` jsonb); при
входе копия аккаунта на устройстве и облачная сливаются по максимуму (`mergeProgress`). Таблица и правила RLS —
`supabase/progress.sql`; в шаблоне письма Magic Link стоит код `{{ .Token }}`, а не ссылка.

## Спрайты

```
art/concepts/            исходные листы концептов 1536×1024 (towers-tiers — башни по ярусам, PNG со своей прозрачностью, enemies, bosses,
                         enemies/factions — враги пяти фракций, enemies/ice-legion — ледяной легион;
                         props/ — связка, тройная связка и замок: снимки экрана на тёмном фоне-градиенте)
scripts/slice_sprites.py нарезка листов: прозрачный фон без ореола, рамки и размеры фигур
public/sprites/          PNG (tower_<тип>_<уровень>, enemy_*, enemy_<тип>_<уровень>, boss_1..5, binder, binder_triple, castle) и sprites.json
```

`sprites.json` для каждой фигуры хранит размер файла, `drawH` (высота на поле в px; файл втрое
крупнее), точку привязки по низу (`anchorX`, `anchorY`) и `facing` (куда смотрит на листе).
Перенарезка: `python3 scripts/slice_sprites.py` (нужны numpy и Pillow).
Лист-каталог всех персонажей с подписями — `docs/characters.png`; пересобрать: `npm run dev`, затем
`node scripts/character_sheet.mjs` (нужен Playwright, фигуры рисует сам движок). Враг рисуется спрайтом своей
фракции `enemy_<тип>_<уровень>` в его цветах, если такой есть; иначе общий `enemy_<тип>` получает оттенок
цвета фракции кодом. Анимация — только преобразования спрайта в `engine.ts`: шаг врага
(`GAIT`, от пройденного пути), парение летунов, дыхание и отдача башни после выстрела, падение
убитого врага (`corpses`, не больше 30), кольца уровня и значок специализации башни рисуются кодом. Связанная пара — два одиночных спрайта своих уровней
в полный размер, по диагонали в одной клетке (основная выше и сзади, вторая ниже и спереди), и эффект `drawBond`: бирюзовое свечение оснований и маленький пульсирующий кристалл между ними,
сила растёт с уровнями обеих частей; у Стрелка и Мага светлая обводка основания (`TOWER_RIMS`) для тёмных карт. Значок свойств под башней — двухбуквенные коды с силой
(`specBadge` в `towerStats.ts`: «Ог×2·Мр»), у пары из связки свой значок у каждой башни. Если спрайт не
загрузился, движок рисует прежние геометрические фигуры. Связка на поле — кристальный столп (`binder`), тройная — кристальная корона (`binder_triple`), замок — кольцо
с тремя опорами (`castle`, выше клетки; выбор Артура 2026-10-30); связки, башни и замок рисуются в одном порядке
по глубине. Врагов на поле рисуем крупнее файла:
`ENEMY_DRAW_SCALE` ×2,2, боссов `BOSS_DRAW_SCALE` ×3,5 (только отрисовка, радиусы и баланс не меняются).

## Игровые правила (кратко)

- 5 уровней, у каждого своя фракция с особенностью и боссом; 12 волн, в последней — босс.
- Шестая фракция — Люди (`CONFIG.factions[5]`, числа `CONFIG.humans`; своей карты нет, `CONFIG.levelCount` = 5): только в
  бесконечном режиме и дуэли (выбор Артура 2026-10-31). Особенность «Полевое восстановление»: враг, которого 3 с не ранили,
  восстанавливает 2 % здоровья в секунду; босс — Командор экспедиции, раз в 12 с «Врата»: он и до 5 пеших врагов в 3 клетках
  переносятся на 2 клетки вперёд (`advanceAlongPath`, тем же путём рывок Королевы теней); числа утвердил Артур 2026-10-31.
- Бесконечный режим (выбор в меню, `engine.endless`, `CONFIG.endless`): 12 волн повторяются по кругу
  (`waveDefinition`), босс каждую 12-ю волну, HP растёт с номером волны без предела, каждый пройденный
  круг даёт +25 % врагов, между волнами 45 с. Победы нет, хранится рекорд волны. Враги выбираются в меню отдельно от карты
  (список «Враги»: хозяева карты или любая из шести фракций, `startLevel(level, diff, true, faction)`); рекорд — по ключу
  `endlessRecordKey` (номер карты для её фракции, иначе карта × 10 + фракция: 16 — Пограничье против людей).
